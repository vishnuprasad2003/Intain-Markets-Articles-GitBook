# Status & Approval Philosophy

Every transaction moves through defined stages. A qualified person must authorize each move to the next stage. **Status** shows where an item is and which actions are available. **Approval** is the gate between stages.

## How It Works

**Status controls actions.** Buttons turn on or off with the status. A term sheet in **Draft** can be edited; in **In review** it cannot. A deal in **Active** can start repayment; one in **Settlement In Progress** cannot.

**Stages stay in order.** Items cannot skip stages. A pool moves Created → Preview → Deal in sequence. Jumping from Created to Deal directly is not possible.

**Final statuses end the workflow.** **Cancelled**, **Rejected**, and **Closed** end the item. To try again, create a new item.

## The Maker-Checker Principle

The person who creates an item is never the person who approves it.

| Who creates | Who approves |
|---|---|
| Borrower creates term sheet | Facility agent approves |
| Issuer creates asset sale deal | Underwriter approves |
| Borrower submits funding request | Facility agent approves |
| Issuer starts repayment | Investor confirms |
| Facility agent sets up master commitment | Lenders approve |

## Change Request vs Rejection

| Aspect | Change Request | Rejection |
|---|---|---|
| Item editable? | Yes | No |
| Can resubmit same item? | Yes | No |
| Workflow | Returns for revision | Stops |
| Next step | Edit and resubmit | Create a new item |

## Key Principles

- **Every item has one status** — answers where the item stands right now
- **Approvals are active decisions** — nothing is approved automatically because time passed
- **History stays on record** — status changes, approvals, and actions are permanently recorded
- **Duties stay separate** — the platform does not allow the same person to both create and approve the same item
- **A disabled button is the workflow protecting parties** — not a broken control
