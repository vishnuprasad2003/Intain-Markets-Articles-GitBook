# Token Approval

## Overview

This guide explains the token approval process within the Credit Facility module. Token approval is a multi-step workflow that begins when the facility agent approves a funding notice, continues through FT (fungible token) contract deployment on the blockchain, requires the borrower to authorize token transfers via an on-chain ERC-20 approval, and concludes when the facility agent completes e-signatures for each participating lender. Understanding this workflow is essential for all participants — borrowers, facility agents, and lenders — because each role has specific actions and dependencies at different stages.

![Issuer Token Approval](<.gitbook/assets/Issuer_Token_Approval (3).png>)

## Who Can Use This

* **Borrowers (Issuers)** — Responsible for approving the token transfer after tokens are generated
* **Facility Agents (Underwriters)** — Responsible for approving the funding notice, triggering token generation, and e-signing for each lender
* **Lenders** — Receive visibility into the funding notice after their e-sign is complete, then transfer funds and confirm settlement

## When This Is Used

Token approval occurs within the funding notice lifecycle, specifically after:

1. A funding request has been submitted by the borrower and approved by the facility agent (status: `APPROVED`)
2. A funding notice has been auto-generated (status: `PENDING_TOKEN_GENERATION`)
3. The facility agent has approved the funding notice, triggering FT contract deployment
4. Tokens have been generated on the Avalanche C-Chain (status: `TOKEN_GENERATED`)

This is not a standalone action — it is embedded in the broader credit facility drawdown workflow.

## Step-by-Step Process

### Step 1: Facility Agent Approves the Funding Notice

**Actor:** Facility Agent

After a funding request is approved and the funding notice is auto-generated with `PENDING_TOKEN_GENERATION` status:

1. The facility agent navigates to **Credit Facility → Active Facilities**
2. Locates the funding notice under the relevant master commitment
3. Reviews the funding notice details, including the drawdown amount and lender allocations
4. Clicks **Approve** on the funding notice

**What Happens:**

* The platform deploys a new ERC-20 FT (fungible token) contract on the Avalanche C-Chain
* The contract is named using the facility name and funding notice identifier (generated by `buildCreditFacilityFtTokenName` and `buildCreditFacilityFtSymbol`)
* The deployed contract address is recorded as `ftContractAddress` on the funding notice
* The total token supply is minted and assigned to the borrower's wallet
* FT ownership is configured for the facility
* The funding notice status advances to **TOKEN\_GENERATED**
* Each lender's entry in `tokenDistribution` is initialized with:
  * `lenderApprovalStatus: 'PENDING'`
  * `esignatureStatus: 'pending'`
  * `tokensAllocated` based on their participation percentage
  * `commitmentAmount` based on their commitment in the master commitment

### Step 2: Borrower Approves the Token Transfer

**Actor:** Borrower

Once the funding notice reaches `TOKEN_GENERATED` status:

1. The borrower navigates to **Credit Facility** and finds the funding notice
2. Reviews the token distribution details:
   * Total supply and FT contract address
   * Per-lender allocations, participation percentages, and commitment amounts
3. Clicks **Approve Token**
4. Enters their **Wallet Private Key** in the approval modal
5. Clicks **Approve** to submit the on-chain transaction

**What Happens On-Chain:**

* The borrower's wallet signs an ERC-20 `approve` transaction on the FT contract
* This authorizes the platform's escrow/admin wallet to transfer the total token supply on the borrower's behalf
* The transaction is submitted to the Avalanche C-Chain and a `transactionHash` is recorded

**What Happens in the Platform:**

* The approval is recorded in the funding notice's `actionHistory`
* The `lenderApprovalStatus` tracking begins for the facility agent's next steps
* The facility agent's E-sign action becomes available

### Step 3: Facility Agent E-Signs for Each Lender

**Actor:** Facility Agent

After the borrower's token approval:

1. The funding notice action shows **E-sign (0/n)** where `n` is the number of participating lenders
2. The facility agent clicks the E-sign action
3. For each lender, the platform opens an Adobe Sign (or ZohoSign) window
4. The facility agent completes the e-signature for that lender
5. The e-sign counter progresses: `(0/n) → (1/n) → (2/n) → ... → (n/n)`

**What Happens Per Lender:**

* The lender's `esignatureStatus` updates from `pending` to `ESIGN_COMPLETED`
* A signed PDF document is generated and stored
* The signed document is recorded in the e-signature provider's collection (`adobesign_requests` or `zohosign_requests`)
* That specific lender gains visibility into the funding notice
* A notification is sent to the lender's organization

**E-Sign Progress Tracking:**

| E-Sign Status | Meaning                                            |
| ------------- | -------------------------------------------------- |
| E-sign (0/3)  | No lenders have been signed yet                    |
| E-sign (1/3)  | Facility agent completed e-sign for 1 of 3 lenders |
| E-sign (2/3)  | Facility agent completed e-sign for 2 of 3 lenders |
| E-sign (3/3)  | All lenders signed — e-signature process complete  |

The platform tracks `eSignatureTotalCount`, `eSignaturePendingCount`, and `eSignatureStatus` at the funding notice level, as well as individual `esignatureStatus` per lender in the `tokenDistribution` array.

### Step 4: Lenders Act on the Funding Notice

**Actor:** Each Lender

After their e-sign is complete, each lender:

1. Sees the funding notice in their **Credit Facility** or **Opportunities** view
2. Reviews the funding notice details, including their allocated amount and token distribution
3. Transfers the required funds through their banking channel
4. Returns to the platform and clicks **Confirm and Settle**

**What Happens:**

* The platform executes an FT token transfer from the borrower's approved allocation to the lender's wallet
* The blockchain `transactionHash` for the transfer is recorded in the lender's `tokenDistribution` entry
* The lender's `mintingStatus` updates to `completed`
* The settlement is recorded via the settlement module (`markSettled`)

### Step 5: Funding Notice Completion

When all lenders have completed their fund transfers:

* The system checks `isAllLendersFtTransferred(tokenDistribution)` — this returns `true` when every lender's `mintingStatus` is `completed`
* The funding notice status automatically transitions to **TOKEN\_TRANSFERRED**
* The completion is logged in the funding notice's status history
* The full drawdown cycle is now complete

## Token Approval Status Summary

| Status                     | Stage                            | What It Means                                                     |
| -------------------------- | -------------------------------- | ----------------------------------------------------------------- |
| `PENDING_TOKEN_GENERATION` | After funding request approval   | Funding notice created, awaiting FA approval for token deployment |
| `TOKEN_GENERATED`          | After FA approves funding notice | FT contract deployed, awaiting borrower token approval            |
| Token Approved (borrower)  | After borrower approves          | On-chain ERC-20 approval granted, FA can now e-sign               |
| E-sign (0/n → n/n)         | FA e-signing                     | Progressive e-signature for each lender                           |
| `TOKEN_TRANSFERRED`        | After all lenders settle         | All FT tokens delivered, drawdown complete                        |

## Rules & Validations

| Rule                              | Details                                                                                                                                                              |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Sequential Dependency**         | Each step must complete before the next can begin: FA Approve → Token Generated → Borrower Approve → FA E-Sign → Lender Settle                                       |
| **Status Enforcement**            | The system validates the funding notice status at each step and rejects out-of-order actions                                                                         |
| **Lender Eligibility**            | Only lenders with `esignature_completed` status on the master commitment are included in the token distribution                                                      |
| **Per-Lender Visibility**         | Each lender sees the funding notice only after their individual e-sign is complete                                                                                   |
| **Idempotency**                   | If a step has already been completed (e.g., tokens already generated, borrower already approved), the system returns an informational response without re-processing |
| **On-Chain Finality**             | The borrower's token approval and each lender's FT transfer are blockchain transactions — permanent and irreversible                                                 |
| **No E-Sign for Funding Request** | E-signatures apply to the funding notice, not the funding request approval                                                                                           |

## What Happens Next

**After Token Approval Workflow Completes (`TOKEN_TRANSFERRED`):**

* The borrower has received the drawn-down funds from lenders
* Lenders hold FT tokens representing their participation in the drawdown
* The funding notice is archived with a complete audit trail including all transaction hashes, timestamps, and actor records
* The credit facility utilization is updated to reflect the completed drawdown
* Future funding requests can be created against the remaining borrowing capacity
