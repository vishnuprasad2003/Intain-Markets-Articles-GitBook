🟦 DOCUMENT TYPE A — Platform Foundation Documents

(Appear once, at the beginning)

Purpose:
Orient users, set mental models, explain philosophy, establish foundational understanding

Used For:
- What is Intain Markets
- Status & approval philosophy
- End-to-end traceability
- Controls & accountability
- Why approvals exist

Structure (Fixed):
1. Title
2. Overview
   - Brief introduction to the concept
   - Why this matters to users
   - Context and importance
3. How the Platform Is Designed
   - Platform-level design principles
   - Architectural approach
   - System-wide considerations
4. What This Enables for Users
   - Benefits and capabilities enabled
   - User value proposition
   - How users benefit from this design
5. Key Principles to Understand
   - Core principles users should know
   - Important concepts to grasp
   - Foundational knowledge

Writing Guidelines:
📌 No steps or procedures
📌 No feature lists
📌 Strategic explanation only
📌 Natural, user-friendly language
📌 Focus on "why" and "what" not "how"
📌 Detailed explanations for complete understanding

🟩 DOCUMENT TYPE B — Role & Access Documents

Purpose:
Explain roles, permissions, and access capabilities

Used For:
- User Roles & Responsibilities
- Who can do what
- Enabled vs Disabled actions
- Roles in Credit Facilities

Structure:
1. Title
2. Overview
   - Introduction to roles and access
   - Why understanding roles matters
   - Context for role-based access
3. Roles Covered
   - List of roles explained
   - Role descriptions
   - Role context
4. What Each Role Can Do
   - Detailed capabilities for each role
   - Actions available to each role
   - Permissions and limitations
   - Clear explanations of capabilities
5. Important Access Notes
   - Key points about access control
   - Important restrictions or considerations
   - How access works in practice
   - Additional context about permissions

Writing Guidelines:
📌 Clear role descriptions
📌 Detailed capability explanations
📌 Natural language, non-technical
📌 Focus on what users can do, not technical implementation

🟧 DOCUMENT TYPE D — Process / How-To Documents

Purpose:
Provide step-by-step instructions for completing tasks

Used For:
- Pool creation & sharing
- Loan management
- Approvals, submissions, reviews
- Term sheet submission
- Funding requests creation
- Token approval
- Facility creation

Structure:
1. Title
2. Overview
   - What this process accomplishes
   - Why users need this
   - Context for the process
3. Who Can Use This
   - Roles that can perform this process
   - Who should use this guide
   - Role-specific considerations
4. When This Is Used
   - Situations requiring this process
   - When to use this guide
   - Appropriate contexts
5. Step-by-Step Process
   - Detailed step-by-step instructions
   - Clear action items
   - What to do at each step
   - Expected outcomes
6. Rules & Validations
   - Business rules that apply
   - Validation requirements
   - Constraints and limitations
   - Important restrictions
7. What Happens Next
   - Outcomes after completion
   - Next steps in workflow
   - What to expect
   - Follow-up actions

Writing Guidelines:
📌 Clear, actionable steps
📌 Detailed explanations for each step
📌 Natural language instructions
📌 Complete coverage of the process
📌 User-friendly guidance

   - Complete lifecycle explanation

📌 Clear status descriptions

🟨 DOCUMENT TYPE J — Concept / Module Overview Documents

Purpose:
Explain what a concept/module is, its purpose, key components, and how it works

Used For:
- Pools Overview
- Loans Overview
- Credit Facilities Overview
- Master Commitment Overview
- Funding Requests Overview
- Funding Notices Overview

Structure:
1. Title
2. Overview
   - Introduction to the concept
   - Why this concept matters
   - Context and importance
3. What [Concept] Is
   - Clear definition
   - What it represents
   - Core nature of the concept
   - Detailed explanation
4. Purpose and Use Cases
   - Why this concept exists
   - What it's used for
   - Common use cases
   - When it's needed
5. Key Components
   - Main elements of the concept
   - Important parts
   - Component descriptions
   - How components relate
6. How [Concept] Works
   - How the concept functions
   - Operational mechanics
   - Process flow
   - How it operates
7. Important Points to Know
   - Key information users should know
   - Important considerations
   - Critical points
   - Additional context

Writing Guidelines:
📌 Explains the concept itself, not platform design
📌 Focus on what it is and how it functions
📌 Natural, user-friendly explanation
📌 Detailed concept explanations
📌 Module-specific context, not platform-wide design

Purpose:
Explain complete workflows from start to finish

Used For:
- Token Generation and Issuance
- E-Signature Workflow

Structure:
1. Title
2. Overview
   - Introduction to the workflow
   - Why this workflow matters
   - Context and importance
3. Workflow Overview
   - Overall workflow description
   - Complete flow explanation
   - How the workflow operates
   - End-to-end process
4. Key Stages
   - Main stages in the workflow
   - Stage descriptions
   - What happens at each stage
   - Stage progression
5. How the Workflow Progresses
   - Progression through stages
   - How stages connect
   - Flow between stages
   - Complete progression explanation
6. Important Points to Know
   - Key information about the workflow
   - Important considerations
   - Critical points
   - Additional context

Writing Guidelines:
📌 Explains complete workflows
📌 Shows progression through stages
📌 Avoids step-by-step instructions (use Type D for that)
📌 Focus on workflow understanding, not task execution
📌 Natural language explanations

Final Guidance (Very Important)

Golden MNC Rule:
Not all pages are "how-to".
Mature platforms explain, orient, and justify — not just instruct.

Key Principles:
1. Use natural, user-friendly language throughout
2. Provide detailed explanations for complete understanding
3. Focus on user needs and understanding
4. Avoid technical jargon unless necessary
5. Ensure consistency across all document types
6. Maintain clear structure and organization
7. Provide comprehensive coverage of topics
8. Use clear, descriptive titles and headings
